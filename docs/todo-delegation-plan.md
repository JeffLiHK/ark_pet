# ArkPet 桌面功能子代理分派計畫

狀態為待確認。[功能規劃](todo-implementation-plan.md) 定義 20 項功能的操作、實作與個別驗收。本文件定義可以交付的工作包及整合順序。批次代表程式相依關係，實際發佈版本在功能驗收後決定。

## 第一批　獨立開工與可行性驗證

主代理最多同時分派三項，依下列順序開工。兩個工作包若同時需要改同一段 XAML 或程式方法，由主代理排定先後。

| 工作包 | 主要入口與交付 | 交接條件 |
| --- | --- | --- |
| #10 今日運勢 | `App.Layout.cs`、`PetSettings.cs` 及主介面的輪值區。交付籤文、日期與角色保存及手動入口。 | 驗證兩個日期、當天重啟及舊設定。保存欄位在設定視窗回填時保留。 |
| #13 字幕主題 | `PetWindow.xaml` 的 `VoiceBubble`、字幕回呼與設定的語音頁。交付樣式、字體、工作區置放及通用氣泡入口。 | 回報 #02 能使用的氣泡呼叫方式及圖案／字幕的生命週期。 |
| #01、#04 音訊原型 | 同一工作包分別驗證擷取端點活躍狀態與輸出音量峰值。在 Windows 10 上測會議、錄音、靜音、預設／非預設裝置及插拔。 | 回報哪些應用程式及裝置可辨識、探測延遲、資源釋放及可重現步驟。分別判定麥克風觸發與節奏效果能否進入實作。 |
| #12 合照編碼原型 | 先用兩個合成物件與半透明邊緣產生透明 GIF／WebM 樣檔，再在目標 Windows、瀏覽器及剪輯器解碼。 | 回報輸出時長、尺寸、幀率、透明結果、編碼耗時與部署依賴。未驗過 Alpha 的 WebM 編碼路徑留在原型。 |
| #17 Spine 素材原型 | 從 `SpineFrameCache.cs`、`SpineFrameRenderer.js` 追查可用骨架和片段。挑一套已核對素材驗證基建與戰鬥片段能否共享模型。 | 交付測試造型 ID、骨架類型、真實片段名稱、構圖比較與快取相容性結果。素材缺失時回報所需檔案或以自製素材完成載入測試。 |

### 共用的位置與顯示規則

- **顯示**　小人「想顯示」由既有 `WantsVisible` 表達。手動情境、自動避讓、釘選目標暫時不可用等因素各自提供顯示限制。實際顯示條件由同一入口套用，任一限制解除時重新計算其餘限制。滑鼠穿透也要同時考慮手動互動設定與自動覆寫。 [現有顯示與情境](../src/ArkPet/Desktop/PetWindow.xaml.cs#L241)
- **位置**　同一隻小人每個更新區間只允許一個位置來源。手動拖曳中止可取消的臨時活動，釘選可由拖曳解除。短時活動如賽跑、追逐或探頭只收取符合資格的小人，讓位給拖曳及顯示抑制。一般路徑中，下落與疊羅漢先決定可用支撐，隊列、道具、家具或閒置陪伴各提供一個可取消的走路目標，無目標時回到日常散步。跨螢幕傳送只接手明確獲准的日常邊緣路徑。
- **座標**　跨螢幕選擇、碰撞和移窗使用實體像素。速度與安全間距可用 DIP 設定，依當前或目的螢幕 DPI 換算。儲存位置沿用工作區比例和腳底錨點。 [現有錨點與復位](../src/ArkPet/Desktop/PetWindow.Activity.cs#L105)
- **走路接點**　第一個實作者交接的資訊至少涵蓋要求走到哪個腳底點、預期走面、是否可達、誰目前佔用、到達／中止結果，以及何時恢復自由散步。先用一個呼叫者驗證可重用，再由後續工作包加入實際所需參數。
- **暫時狀態**　釘選、拋擲、探頭、疊羅漢、追逐與賽跑均有明確取消或釋放條件。桌面配置擷取仍以偏好或活動開始前的有效位置為準。設計應涵蓋關窗、換裝、停止活動、隱藏、螢幕移除及程式結束。

## 第四批　多小人狀態整合

- **#18 疊羅漢**　交付可驗證的支撐關係、四隻上限與解體回退。依賴 #03A 拋擲與碰撞，整合時和釘選、傳送、走出支撐邊緣一起驗收。
- **#19 追逐**　交付接近、停止、驚喜動作、游標旁圖示及取消。依賴 #03A 目標走路、#01 有效情境，與 #06 跟隨偏好、#11 閒置陪伴一起驗收。
- **#20 賽跑**　交付可取消的參賽狀態、跑道、倒數、勝負和復原。重用 #19 已驗證的短時活動進出規則。先用可控時間和種子驗證勝負，最後用混合造型、DPI 與物理模式驗證畫面。

## 分派時附上的工作資料

每個子代理取得功能編號與相應規格、可修改的程式／XAML 區段、先決工作的提交或可用呼叫方式、所需測試素材及須回傳的驗收案例。原型工作包回傳可行性、限制與重現步驟。功能工作包回傳變更檔案、入口、狀態和設定欄位、實測結果與尚待驗證項目。主代理負責合併共用 XAML、`PetSettings`、`App.xaml.cs`、`App.Layout.cs`、`README.md`，以及跑整合驗收。

功能更動應一併更新 README 的使用方式和發佈狀態。新增本機設定欄位要測舊設定缺欄位的預設行為，以及視窗開著時儲存其他選項的保留行為。涉及長時間工作或裝置事件時，驗證取消、重試、退出或裝置移除後的資源釋放。

## 整合驗收

1. 執行 `dotnet build ArtPet.slnx -c Release`，並用 `dotnet run --project src/ArkPet/ArkPet.csproj -c Debug` 從原始碼驗收。對純規則增加可重現的輸入／輸出案例，優先涵蓋日期切換、匯入驗證、隨機種子及支撐循環。
2. 用 Windows 10 單螢幕及可取得的混合 DPI 雙螢幕測試，另於可用 Windows 11 測試主題、會議、前景與裝置變更。實測紀錄列明 Windows 版本、DPI、素材、重現步驟和結果，無法執行的組合標為未驗收。
3. 複驗點擊穿透、前景焦點、手動拖曳、通知區、造型切換和隱藏恢復。以短按互動、投餵、跟隨同時啟用驗證控制權不衝突，再交叉測專注、釘選最小化、拔除螢幕及活動取消。
4. 對移窗、音訊及匯出工作量測前後 CPU、記憶體與幀率。至少以單隻、四隻和全隱藏比較。記錄 GIF／WebM 峰值記憶體、輸出速度與取消後的檔案狀態。 [現有驗收指南](testing-and-acceptance.md)
