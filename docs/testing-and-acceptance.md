# 自動化測試與 Prototype 驗收

用自動化測試保護動畫、素材清單、設定和位置計算等可重複的規則。用 Windows 上的獨立測試宿主確認點擊穿透、拖曳、通知區和換裝行為。霍爾海雅的預設造型和「歷世流風」是正式驗收的兩套素材。[產品需求](prototype-plan.md) · [UI／UX 設計](ui-ux.md)

## 測試準備

- 測試與驗收期間禁止啟動 Art Pet 正式應用程序。勿執行 `ArtPet.Windows.exe`，也勿透過 `dotnet run --project src/ArtPet.Windows/ArtPet.Windows.csproj`、IDE 或發佈包啟動應用程式。可執行建置、靜態檢查、自動化測試，或在獨立測試宿主載入所需元件。若現有工具無法驗證某項正式程序行為，將該項記為「未驗收」。
- 開發測試用同一素材格式的兩套自製幾何圖形影格，準備可用、缺檔和損毀的版本。測試期間用獨立暫存目錄建立素材和設定檔。
- 在 `ArtPet.Core.Tests` 用 MSTest 測 C# 邏輯。動畫時間由測試輸入，指定播放前後的時間點，讓案例每次可用同一條件重跑。PNG 解碼與 Windows 視窗行為由獨立測試宿主驗證，素材與設定使用隔離的測試目錄。
- 測試專案建立後，從專案根目錄執行。日常修改先跑相關案例，出測試包前跑完整測試專案。

```powershell
dotnet test tests/ArtPet.Core.Tests/ArtPet.Core.Tests.csproj -c Release
```

## 自動化測試

- **素材清單。** 讀取合法的第 1 版清單，應取得角色、預設造型、圖卡順序、畫布、錨點和片段。分別測試不支援的版本、重複造型 ID、缺失的預設造型、畫布或錨點無效、幀率超出範圍與相對路徑越出素材資料夾。每種不合規清單應回傳明確的欄位或路徑錯誤。可選的立繪和摸摸片段允許省略。
- **待機與摸摸。** 從片段起點、結尾和跨過循環邊界取影格，確認待機能循環並跳到經過時間對應的影格。互動從首幀播放一次，期間再點一下仍沿用當前反應，結束回到待機。缺少摸摸片段時走微風回應。
- **設定與寫入。** 設定檔缺失時得到預設大小和置頂值。寫入包含素材資料夾、角色、時裝、螢幕、錨點、大小和置頂的設定，再讀取後逐項比對。測試缺漏欄位、超出範圍的值、損毀或未知版本。驗證能用預設值啟動，下次成功寫入前可保存原檔，寫入失敗時先前的有效設定仍可讀取。
- **位置與縮放。** 用雙螢幕、座標為負的副螢幕和不同的工作區大小測試。換裝與縮放沿用腳底錨點，靠邊時小人整體仍在工作區內。原螢幕不存在時，位置計算回到主螢幕右下角。

## Windows 實機驗收

以下為獨立測試宿主應覆蓋的行為。以測試程序或元件層級重現流程。

1. **首次載入和選擇素材。** 使用空白測試設定，驗證通知區的資料夾與結束指令。選取有效素材後，霍爾海雅以預設造型在右下角待機。已載入角色時再選取消或選到損毀的資料夾，原先的角色與素材設定應可繼續使用。模擬重複啟動時，原有小人和通知區圖示各維持一個。
2. **摸摸、拖曳及焦點。** 在有可點擊內容的視窗上測試。點透明區域會操作下方視窗，點小人會播放回應並保留原本的前景。測試按下後離開輪廓再放開、連點、拖曳到不同 DPI 的螢幕。僅有效短按會播摸摸，拖曳放開時小人仍可見並保存新位置。
3. **換裝與同時操作。** 選定「歷世流風」，預設造型持續播放直到新造型整套載入完成，新造型於原位開始待機。再測試讀取中點回使用中的造型、連續點選、換裝同時拖到不同 DPI 的螢幕，以及載入時關閉衣櫃。確認最後選擇生效，縮放仍使用正確造型。候選缺少待機影格時顯示錯誤，原造型可繼續使用。缺少立繪時顯示待機首幀，缺少摸摸影格時播放微風。
4. **通知區與鍵盤。** 隱藏小人，從通知區開衣櫃並換裝，叫回時應穿著新造型。用 Tab 和方向鍵移動焦點，用 Enter 或空白鍵套用，Esc 關閉衣櫃。檢查「使用中」、「套用中…」及「素材無法讀取」的文字、焦點區分和螢幕閱讀器名稱。以 Windows 100%、125% 和 150% 顯示比例確認選單與視窗可用。
5. **設定重讀與錯誤回復。** 保存位置、大小、置頂和造型後，以新的測試工作階段重讀設定。小人應按保存的設定顯示並從待機開始。再分別測試拔除副螢幕、移走上次使用時裝、移走資料夾和設定損毀，核對主螢幕、預設造型或通知區的回退行為。[資料保存與設定](prototype-plan.md#資料保存與設定)
6. **自由模式。** 驗證預設步速、切換步速後的位移、原地發呆和睡眠，以及抵達左右工作區邊緣後折返。記錄多個呈現週期內的位置，檢查連續位移與單次停頓，並驗證互動及隱藏時停止走動。
7. **Release 測試包。** 使用架構文檔的 Windows x64 發佈指令產出測試包，檢查封裝內容。使用獨立測試宿主在 Windows 11 和目標 Windows 10 21H2 LTSC 驗證可獨立測試的元件行為。[發佈指令](architecture.md#實作與測試)

## 效能驗收

在獨立測試宿主載入 Release 組建的元件和兩套霍爾海雅素材，記錄測量方式及可覆蓋的範圍。數值門檻集中在[架構的效能規格](architecture.md#效能設計與發佈門檻)。

- **待機和隱藏。** 關閉衣櫃並等資源載入完成，各次量測前穩定 15 秒。依架構規格分別取 60 秒的可見待機與隱藏資料，記錄 CPU、GPU、私有記憶體和影格更新。比較預設大小與 150% DPI 下的最大尺寸。CPU 須換算為單一邏輯核心的使用量，GPU 則比較同一引擎。
- **流暢度。** 記錄桌面視窗切換影格的時間點，計算每秒更新次數、95 百分位間隔和最大停頓。另在螢幕上確認實際呈現。另取至少 20 次有效摸摸的放開至回應時間，以及連續拖曳時的位置更新間隔。記錄樣本數與實測值。
- **多次換裝。** 在兩套時裝間切換，合計成功套用 20 次，記下換裝前、過程峰值與穩定後的程序私有記憶體。同步觀察背景讀取時舊造型有否持續播放，並確認完成後舊影格不會持續累積。

## 驗收紀錄

每次記錄測試包版本、Windows 版本、CPU／GPU、DPI、使用的素材、步驟、預期與實測結果。有問題時附上重現流程或量測記錄位置。結果標為「通過」、「失敗」或「未驗收」。完整的自動化測試、Windows 操作案例及效能門檻均通過後，才完成 Prototype 驗收。
